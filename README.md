## 중간고사: 내 요청 목록 (7주차에서 새로 추가한 것)

7주차에는 추천 요청을 보내면 완료 화면에서 끝났습니다. 중간고사에서는 그 끝에 "**내 요청 목록**"을 이어서, 보낸 요청이 목록에 쌓이고 상태(검토 대기·취소됨)를 보면서 **요청을 취소하거나 다시 요청**할 수 있게 했습니다.

- **사용자·목표와의 연결:** JJ픽의 주요 사용자는 살림템을 사기 전에 짧은 영상으로 확인하고 싶은 사람이고, 추천 요청의 목표는 "고민 중인 제품을 영상으로 추천받기"입니다. 요청은 영상이 나올 때까지 기다리는 일이라, 기다리는 동안 무엇을 요청했는지 보고 필요 없어지면 취소하는 행동이 이 목표에 바로 이어진다고 보았습니다.
- **7주차와 다른 점:** 7주차는 요청 한 건을 입력·선택·확인해서 보내는 흐름이었고, 이번 기능은 이미 보낸 여러 요청의 **상태를 바꾸는**(검토 대기 ↔ 취소됨) 새 경로입니다. 입력 오류 안내나 확인·수정을 반복한 것이 아니라 목록 추가, 취소 확인 창, 다시 요청, 빈 목록 안내가 새로 생겼습니다.
- **왜 넣었나:** 요청을 보낸 뒤 "내가 뭘 요청했더라?", "다른 걸로 바꾸고 싶은데" 하는 상황에서 다시 확인하고 마음을 바꿀 길이 없었습니다. 영상 준비 전이라면 취소할 수 있어야 사용자가 부담 없이 요청할 수 있다고 생각했습니다.
- **연결 지점:** 흐름의 **끝**(완료 화면의 "내 요청 목록 보기", 요청을 보내면 자동 추가)과 **앞**(① 제품 입력에서 이미 요청한 제품인지 검사)에 연결했습니다. 메뉴에도 "내 요청"을 추가했습니다.
- **프로토타입 한계:** 서버 없이 브라우저에서만 동작해서, 새로 고침하면 목록이 비워집니다.
  - 9주차에 목록을 브라우저 저장소(`localStorage`)에 저장하도록 바꿔서, 지금은 새로 고침해도 남습니다. 위 문장은 중간고사 제출 당시 기준입니다.

### 구현 과정

1. **기능 정하기:** 7주차 흐름이 완료 화면에서 끝나서, 요청을 보낸 다음 사용자가 할 일이 없다는 점부터 생각했습니다. 시험 예시 중 "완료한 선택을 취소해 상태를 바꾸기"가 영상 추천을 기다리는 JJ픽 사용자 상황에 가장 맞아서 내 요청 목록과 취소로 정했습니다.
2. **HTML:** 추천 요청 섹션 아래에 목록, 빈 목록 안내, 취소 확인 창을 넣고, 완료 화면에 "내 요청 목록 보기" 버튼과 메뉴 링크를 추가했습니다.
3. **CSS:** 검토 대기·취소됨이 글자를 읽지 않아도 구분되도록 배지 색과 취소된 요청의 흐린 모양을 먼저 정하고, 768px 이하 배치를 맞췄습니다.
4. **JavaScript:** 요청을 배열에 넣고 목록을 다시 그리는 부분 → 취소 확인 창 → 다시 요청하기 → 중복 검사 순서로 붙였습니다.
5. **시험하며 고친 점:** 다시 요청이 막혔을 때 문구만 나오니 어떤 요청 때문인지 찾기 어려워서, 막은 원인이 된 요청을 강조하도록 고쳤습니다. 또 ③까지 간 상태에서 목록의 취소된 같은 제품을 "다시 요청하기"하면 같은 제품이 두 번 검토 대기가 되는 경우를 찾아서, 보내기 직전에 한 번 더 검사하도록 고쳤습니다. 요청을 취소하거나 되살린 뒤 "이미 요청한 제품이에요" 같은 지난 안내가 화면에 남는 것도 목록이 바뀔 때 되돌리도록 고쳤습니다. 확인 창은 버튼뿐 아니라 Esc로 닫는 경우도 직접 눌러 보고, 상태가 그대로이고 커서가 원래 버튼으로 돌아오는지 확인했습니다.

### 사용한 코드

- **HTML:** 목록(`ul#requestList`), 빈 목록 안내(`#emptyRequests`), 취소 확인 창(`dialog`)을 추가했습니다.
- **CSS:** 상태 배지(검토 대기·취소됨), 취소된 요청의 흐린 모양, 강조 테두리, 확인 창과 뒤 배경(`::backdrop`), 768px 이하 한 열 배치를 넣었습니다.
- **JavaScript:** 보낸 요청을 배열(`myRequests`)에 객체로 담고, `renderRequests()`가 배열 내용대로 목록·건수·빈 목록 안내를 다시 그립니다. 목록 안 버튼은 `ul` 하나에 click 이벤트를 걸고 `data-action`(cancel·restore)으로 나눴고, 확인 창은 `showModal()`·`close()`와 `close` 이벤트로 처리했습니다.

## 9주차: 추천 요청 폼 개선 (입력 폼과 피드백)

7주차 추천 요청 폼을 고쳐서, 무엇을 입력해야 하는지 도움말로 알려 주고, 잘못 입력하면 고치는 방법을 보여 주고, 제출 중·성공·실패를 구분해 보여 주도록 했습니다. "써 본 비슷한 제품이 있어요"를 체크하면 추가 입력칸이 열리는 조건부 입력도 넣었습니다.

### 추가·수정한 기능

| 구분 | 내용 | 위치 |
|---|---|---|
| 도움말 연결 | 모든 입력칸에 `label`을 연결하고, 입력 조건을 도움말(`.field-help`)로 적은 뒤 `aria-describedby`로 입력칸과 이었습니다 | `index.html` ① 제품·② 예산·써 본 제품·메모 |
| 입력 중 피드백 | 글자 수와 조건 충족 여부를 문구로 표시합니다. 예: "1 / 20자 · 2자 이상 필요" → "4 / 20자 · 조건 충족"(초록). 색만이 아니라 문구로도 구분합니다 | `script.js` `updateItemCount()`, `updateUsedCount()` |
| 오류 해제 | 오류가 뜬 뒤 조건에 맞게 고치면 다시 제출하지 않아도 오류 문구와 빨간 테두리가 바로 사라집니다 | `script.js` 제품 입력칸·써 본 제품 입력칸의 `input` 이벤트 |
| 조건부 입력 | "써 본 비슷한 제품이 있어요" 체크 → "써 본 제품과 아쉬웠던 점" 칸이 나타나고 입력 가능(`hidden` 해제 + `disabled` 해제 + `aria-expanded="true"`). 체크를 풀면 숨기고 `disabled`로 막아 제출·검사에서 빠집니다(쓴 내용은 남아 있어 다시 체크하면 그대로) | `script.js` `setUsedDetail()` |
| 제출 상태 | `form`의 `submit` 이벤트로 처리합니다. 보내는 중에는 버튼을 "보내는 중…"으로 바꾸고 비활성화, 이전·수정 버튼과 체크박스도 잠그고, 진행 문구를 `role="status"`로 보여 줍니다(`aria-busy="true"`). 같은 요청이 두 번 저장되지 않습니다 | `script.js` `setSubmitState()` |
| 성공·실패 | 성공하면 완료 화면으로 이동합니다. 실패하면 3단계에 그대로 머물고, 입력 내용은 유지한 채 "요청을 저장하지 못했어요…" 안내와 함께 버튼이 "다시 보내기"로 바뀝니다 | `script.js` 3단계 `submit` |
| 브라우저 저장 | 보낸 요청을 `localStorage`에 저장해서 새로 고침해도 내 요청 목록이 남습니다. 취소·다시 요청도 저장되고, 저장에 실패하면 상태를 바꾸지 않고 알려 줍니다 | `script.js` `saveRequests()`, `loadRequests()` |

### 실패 처리 조건과 코드 위치

- **언제 실패하나:** 브라우저 저장소에 쓸 수 없을 때입니다(시크릿 창의 저장 제한, 저장 공간 가득 참 등). `saveRequests()`가 `localStorage.setItem()`을 `try…catch`로 감싸 실패하면 `false`를 돌려줍니다.
- **실패하면:** `addRequest()`가 목록에 넣지 않고 `false`를 돌려주고, 3단계 `submit` 처리에서 `setSubmitState('error')`로 바꿉니다. 입력값은 지우지 않으므로 그대로 "다시 보내기"를 누르면 됩니다.
- **직접 확인하는 방법:** 개발자 도구 Console에서 `Storage.prototype.setItem = () => { throw new Error('test'); }`를 실행한 뒤 요청을 보내면 실패 화면을 볼 수 있고, 페이지를 새로 고치면 원래대로 돌아옵니다.

- **기능 이름:** 처음에는 "짧은 영상 추천"처럼 서비스 입장에서 이름을 지었지만, 사용자가 무엇을 할 수 있는지 바로 알 수 있도록 "짧은 영상으로 확인하기"처럼 사용자 행동으로 바꿨습니다.
- **입력 영역:** 처음에는 카테고리 선택과 제품 입력 두 가지를 두었지만, 핵심 행동인 추천 요청에 집중하도록 제품 입력 하나와 버튼 하나로 줄였습니다.

#### 정보 순서를 정한 이유

처음 방문한 사용자가 "무슨 서비스인지 → 무엇을 할 수 있는지 → 어떻게 쓰는지"를 차례로 이해한 뒤 추천을 요청하도록, 입력 영역을 페이지 마지막에 두었습니다. 내용이 길어도 원하는 부분으로 바로 갈 수 있게 `header`에 이동 메뉴를 넣었습니다.

### 3주차 CSS 수정 기록

#### 수정한 내용

- `style.css`를 만들어 `head`에 연결하고, JJ픽 브랜드에 맞춰 크림색 배경과 테라코타 강조색을 적용했습니다.
- 섹션마다 배경색, 테두리, 둥근 모서리, 안쪽 여백을 넣어 카드처럼 구분했습니다.
- 서비스 소개의 글과 이미지, 주요 기능 카드 3개를 Flexbox로 가로 배치했습니다.
- 이동 메뉴, 입력 칸, 버튼에 마우스를 올리거나 선택했을 때의 상태 스타일을 넣었습니다.
- 실제 JJ픽 허브와 같은 서비스로 느껴지도록 허브의 모양을 가져왔습니다: 가운데 정렬 헤더와 동그란 JJ 로고, 필터 칩 모양 메뉴, 아이콘 칸이 있는 기능 카드, 동그란 번호 배지, 고지 박스 모양 안내 문구.

#### 수정 이유

- **속성:** 이용 방법 단계 앞의 동그란 번호 배지(border-radius, background-color)
- **화면 변화:** 단계마다 테라코타색 원 안에 번호가 표시됩니다.
- **사용자에게 좋은 점:** 순서를 한눈에 알 수 있고, JJ픽 허브의 상품 번호와 같은 모양이라 두 페이지를 같은 서비스로 인식할 수 있습니다.

### 4주차 반응형 수정 기록

#### 확인한 문제

- **390px:** 서비스 소개의 그림이 가로 공간을 차지해서, 옆의 글이 한 글자씩 세로로 쌓였습니다.
- **390px:** 기능 카드와 추천 요청 버튼이 화면 오른쪽 밖으로 밀려 가로 스크롤이 생겼습니다.
- **390px:** 이동 메뉴 버튼 안의 글자가 두 줄로 끊겼습니다.

#### 수정한 내용

- **유동 너비:** header, main, footer에 `width: 100%`와 `max-width: 1100px`를 주고, 소개 그림은 `width: 100%`와 `max-width: 360px`로 바꿨습니다.
- **Grid:** 기능 카드 목록을 `repeat(auto-fit, minmax(260px, 1fr))` Grid로 바꿨습니다.
- **768px 이하:** 이동 메뉴를 세로로, 소개 그림을 글 아래로, 기능 카드를 한 열로, 입력창과 버튼을 세로로 배치했습니다. 제목 크기와 여백도 줄였습니다.

#### 달라진 점

| 화면 폭 | 결과 |
|---|---|
| 1100px | 기능 카드 3열, 메뉴·소개·입력 영역은 가로 배치 |
| 769px | 기능 카드 2열, 나머지는 가로 배치 유지 |
| 768px | 메뉴·소개·기능 카드·입력 영역 모두 한 열 |
| 390px | 한 열 배치, 글이 정상적으로 줄바꿈되고 버튼 높이 50px |

네 가지 폭 모두 콘텐츠가 잘리거나 겹치지 않고, 가로 스크롤도 생기지 않습니다.

### 5주차: 사용자 행동에 반응하는 추천 요청

#### 추가한 기능

"추천 요청" 폼에 고민 중인 제품을 입력하고 버튼을 누르면(또는 Enter), 새로 고침 없이 결과를 문구·색·버튼 상태로 바로 알려 줍니다.

| 입력 | 안내 문구 | 스타일·버튼 |
|---|---|---|
| 비어 있음 | 고민 중인 제품을 입력해 주세요. | 빨간 문구 · 입력칸 빨간 테두리 · 입력칸으로 커서 이동 |
| 한 글자 | 제품 이름을 두 글자 이상 입력해 주세요. | 빨간 문구 |
| 이미 추천 모음에 있는 제품 (예: 에어프라이어) | 이미 추천 모음에 있는 제품이에요 — 상품 이름 | 주황 문구 · 판매처 필터를 '전체'로 되돌리고 그 상품 카드를 강조해 보여 줌 |
| 새 제품 | "제품" 추천 요청이 접수되었어요 | 초록 문구 · 버튼이 "요청 완료"로 바뀌고 비활성화(중복 요청 방지) |

다른 제품을 입력하기 시작하면 버튼이 다시 "추천 요청하기"로 돌아옵니다.

#### 사용한 JavaScript

- **연결·선택:** `script.js`를 `body` 끝에서 불러오고, `querySelector`로 폼·입력칸·버튼·결과 문구(`#request-form`, `#item`, `#requestButton`, `#requestMessage`)를 찾습니다.
- **변수:** 바뀌지 않는 버튼 처음 글자는 `const`, 요청 완료 여부(`isRequested`, Boolean)는 `let`으로 저장합니다.
- **조건문·함수:** `checkRequest()`가 `if`로 입력값을 판단해 결과 종류와 문구를 돌려주고, `showResult()`가 `textContent`와 `classList`로 문구·색·버튼 상태를 바꿉니다.
- **이벤트:** `addEventListener('submit', handleRequest)`로 제출을 감지하고 `event.preventDefault()`로 새로 고침을 막습니다. 입력칸의 `input` 이벤트로 버튼을 다시 켭니다.

#### 확인한 것

- 네 가지 입력 모두 문구·색·버튼 상태가 의도대로 바뀌고, 개발자 도구 Console에 오류가 없습니다.
- 1100px · 768px · 390px · 375px에서 결과 문구와 버튼이 잘리지 않고 가로 스크롤이 생기지 않습니다(768px 이하에서는 입력칸과 버튼이 세로로 쌓임).
- W3C HTML·CSS 검사 오류 0개.
- 수업 실습용 페이지라 요청이 실제로 서버에 접수되지는 않습니다.

### 6주차: 이벤트 처리와 탭 UI

> 7주차에 추천 요청이 단계별 흐름으로 바뀌어서, 지금은 글자 수(`input`)가 추천 요청 ① 제품 입력 단계에, 안내 확인 체크박스(`change`)가 ③ 내용 확인 단계에 있습니다. 찜하기와 주요 기능 탭은 그대로입니다. 아래 표는 6주차에 만든 당시 기준입니다.

#### 추가한 이벤트

| 이벤트 | 어디에 | 사용자 행동 | 함께 바뀌는 것 |
|---|---|---|---|
| `click` | 추천 상품마다 "♡ 찜하기" 버튼 | 버튼을 누름 | 버튼 글자(♡ 찜하기 ↔ ♥ 찜했어요) · 버튼과 상품 카드 색 · 위쪽 문구 "찜한 상품 N개" |
| `input` | 추천 요청 입력칸 | 글자를 입력·삭제 | 라벨 옆 글자 수 "N / 20"이 바로 바뀌고, 15자부터 빨간색 |
| `change` | "실습용이라는 점을 확인했어요" 체크박스 | 체크하거나 해제 | 요청 버튼 켜짐/꺼짐(`disabled`) · 안내 문구와 색 |
| `click` | 주요 기능 탭 3개 | 탭을 누름 | 누른 탭만 선택 표시 · 그 탭의 설명만 보임 |

- 찜하기는 다시 누르면 풀리고, 개수도 같이 줄어듭니다.
- 체크하기 전에는 요청 버튼이 회색으로 꺼져 있고, 체크하면 테라코타색으로 켜집니다. 5주차의 "요청 완료" 버튼은 초록색으로 따로 구분했습니다.
- 입력칸에 `maxlength="20"`을 넣어 20자 넘게는 입력되지 않습니다.

#### 탭 UI

원래 카드 3개로 나란히 보여 주던 "주요 기능"을 탭으로 바꿨습니다. 탭마다 설명을 한두 줄 더 넣을 수 있어서, 카드로 늘어놓을 때보다 기능 하나하나를 자세히 볼 수 있습니다.

- **선택 표시:** 고른 탭은 흰 배경 · 테라코타 글자 · 아래 굵은 선, 나머지는 베이지색입니다.
- **콘텐츠 전환:** 탭의 `data-target`으로 보여 줄 패널을 찾고, 다른 패널은 `hidden`으로 숨깁니다.
- **접근성:** `role="tab"` · `aria-selected` · `aria-controls`로 화면 읽기 프로그램도 선택 상태를 알 수 있게 했습니다.

#### 사용한 JavaScript

- `querySelector`로 하나, `querySelectorAll`과 `forEach`로 찜하기 버튼 6개와 탭 3개에 한 번에 이벤트를 연결했습니다.
- 이벤트 함수 안에서 `event.currentTarget`으로 방금 누른 버튼을 찾습니다.
- 화면 변화는 `textContent`(문구) · `classList`(색, `is-saved`·`is-ready`·`is-active` 등) · `disabled`(버튼 상태)로 바꿨습니다.

#### 테스트 결과

| 확인한 것 | 결과 |
|---|---|
| 찜하기 2개 누르기 → 하나 다시 누르기 | "찜한 상품 2개" → "1개", 버튼 글자와 카드 색이 원래대로 |
| 17자 입력 | "17 / 20"으로 바뀌고 빨간색 |
| 체크 전 / 체크 후 | 버튼 꺼짐 / 켜짐, 안내 문구 바뀜 |
| 체크 후 빈칸·이미 있는 제품·새 제품 요청 | 5주차 결과(오류 · 카드 강조 · 요청 완료)가 그대로 동작 |
| 세 번째 탭 누르기 | 세 번째 탭만 선택 표시, 세 번째 설명만 보임 |
| 화면 폭 1100px · 768px · 390px | 가로 스크롤 없음. 768px 이하에서는 탭이 세로로 쌓이고, 입력칸·체크박스·버튼이 한 줄씩 배치됨 |
| 키보드 | Tab으로 탭·찜하기·체크박스·버튼에 이동하고 Enter·Space로 조작됨 |
| Console · W3C 검사 | Console 오류 없음, HTML·CSS 검사 오류 0개 |

### 7주차: 추천 요청 이용 흐름

- 한 화면짜리 추천 요청 폼을 시작 → 제품 입력 → 조건 선택 → 내용 확인 → 완료 흐름으로 바꿨습니다. 자세한 흐름과 시나리오는 위의 "사용자 흐름"·"인터랙션 시나리오"에 적었습니다.
- **유지한 기능:** 5주차 입력 검사(빈칸·한 글자·이미 있는 제품 카드 강조)는 ① 단계에, 6주차 글자 수는 ① 단계 입력칸에, 안내 확인 체크박스는 ③ 단계에 그대로 옮겼습니다.
- **바뀐 점:** 5주차의 "요청 완료" 비활성 버튼은 완료 화면과 단계 표시(모두 ✓)로 바뀌었습니다. 새로 카테고리(라디오 버튼)·예산(선택 목록)·메모(선택 입력)를 받습니다.
- **사용한 JavaScript:** `showStep()` 하나로 `data-step`이 같은 단계만 보이고(`hidden`) 단계 표시·진행 문구를 바꿉니다. 각 단계는 `form`의 `submit`에서 `preventDefault()` 후 필수값을 검사하고, 빠졌으면 `return`으로 멈춥니다. 확인 화면은 들어올 때마다 `showSummary()`로 다시 채우고, 다시 시작은 `form.reset()`과 상태 초기화 함수로 처리합니다.
